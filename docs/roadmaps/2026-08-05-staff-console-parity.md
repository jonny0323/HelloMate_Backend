# 로드맵 — 담당자 웹(직원 관리자 콘솔) 기능 패리티

담당자 웹 프로토타입(`hellomate_teacher.html`)을 기능명세로 정리하면서 뽑은 결함 22건을 메운다.
학생 앱 작업(V7~V9)과 같은 원칙으로 **기존 테이블 삭제·타입 변경 없이 `ADD COLUMN`만** 쓴다.

## 확정한 정책 (명세서에서 "확정 필요"로 남겼던 것들)

명세서에 제안으로 적어둔 안을 그대로 채택한다. 코드에 주석으로 근거를 남긴다.

| 항목 | 확정 |
|---|---|
| 수신 대상 그룹 논리 | **축을 분리**한다. `countryCodes`와 `majors`를 별도 필드로 받고, **축 안에서는 OR, 축 사이는 AND**. 국가만 주면 국가만, 둘 다 주면 교집합 |
| 담당자 부서 권한 | `Staff.department`가 신뢰 소스. 요청의 `department`는 **받지 않는다**. 조회는 같은 대학, 변경(수정·재발송·삭제)은 **같은 부서만** |
| 공지 삭제 | **소프트 삭제**(`deleted_at`). 학생 앱에서도 안 보이게 하되 열람 이력과 문의 스레드는 보존 |
| 담당자 선발신 DM | **허용한다.** 대신 학생의 `CHAT_DIRECT` 알림 설정을 존중하고, 스레드에 개설 주체를 남긴다 |
| 답변 대기 수 | **스레드 기준**으로 통일 (화면의 뱃지/통계 카드 정의 불일치 해소) |
| 평균 열람률 | **가중 평균** (`Σ열람 / Σ수신자`). 공지별 열람률의 단순 평균은 수신자 3명짜리 공지가 312명짜리와 같은 무게를 갖게 되어 왜곡됨 |
| "이번 학기" 기준 | 학사일정 테이블이 없으므로 **설정값**(`hellomate.academic.first-semester-start-month` 등)으로 뺀다. 기본값 3월/9월 |
| 재발송 | 미열람자에게만 알림 재발송. `read`는 **건드리지 않는다**. 24시간 쿨다운 + 횟수 기록 |

## 마이그레이션

전부 `ADD COLUMN`이라 Postgres·H2 양쪽에서 동작한다.

- `V10__add_notice_lifecycle.sql` — `notice`: `status`, `sent_at`, `deleted_at`, `audience_mode`,
  `audience_label`, `resend_count`, `last_resent_at`
- `V11__add_chat_lang_and_thread_origin.sql` — `chat_message.original_lang`,
  `chat_thread.initiated_by`

`notice.title`/`content`는 NOT NULL이라 초안도 빈 문자열로 저장한다(컬럼 제약을 풀지 않기 위함).

## 의도적으로 안 하는 것

- **화면 자체(로그인/서류 심사/신고 처리/생활정보 관리)** — 프로토타입에 없는 화면이고 서버 API는
  이미 있다. 프론트 과제로 남긴다.
- **예약 발송** — 프로토타입에 UI가 없다.
- **학사일정 테이블** — 학기 경계 하나 때문에 테이블을 만들 근거가 부족하다. 설정값으로 시작한다.
